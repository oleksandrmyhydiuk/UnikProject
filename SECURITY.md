# Security Policy / Політика безпеки

## Supported Versions / Підтримувані версії

Наразі оновлення безпеки надаються для наступних версій проєкту **Financial Assistant**:

| Version | Supported          |
| ------- | ------------------ |
| 1.x.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Security Architecture / Архітектура безпеки

Проєкт **Financial Assistant** використовує сучасні криптографічні та системні механізми захисту персональних фінансових даних:

1. **Хешування паролів (Argon2id via `argon2-cffi`)**
   - Паролі користувачів ніколи не зберігаються у відкритому вигляді (plain text).
   - Використовується алгоритм **Argon2id** (переможець Password Hashing Competition, рекомендований OWASP) з автоматичною генерацією криптографічної солі (salt) та підтримкою автоматичного перехешування (`check_needs_rehash`).
2. **Біометрична автентифікація (Windows Hello via `winsdk`)**
   - Підтримується безпарольний вхід через системне вікно **Windows Hello** (FaceID, відбиток пальця або системний PIN-код) за допомогою `UserConsentVerifier`.
   - Перевірка виконується асинхронно (`asyncio`) в окремому потоці `BiometricThread` (`QThread`), що унеможливлює блокування головного потоку інтерфейсу.
3. **Захищене сховище секретів (`keyring`)**
   - Токени стану автентифікації зберігаються у системному сховищі облікових даних ОС (**Windows Credential Manager** / macOS Keychain / Linux Secret Service) через бібліотеку `keyring`.
4. **Захист API-ключів та конфігурації (`python-dotenv`)**
   - Ключі доступу до зовнішніх сервісів (зокрема `EXCHANGERATE_API_KEY`) ізольовані у локальному файлі `.env`, який виключено з системи контролю версій через `.gitignore`.
   - У репозиторії надається лише безпечний шаблон `.env.example`.
5. **Захист бази даних від SQL-ін'єкцій (`sqlite3`)**
   - Усі SQL-запити в `DatabaseManager` (`database.py`) використовують виключно параметризовані вирази (`?` placeholders) та транзакційний відкат (`rollback`) у разі помилок.

 Детальний огляд імплементації безпеки наведено у звіті [report.md](report.md).

## Security Best Practices for Users / Рекомендації для користувачів

- **Не публікуйте файли `.env`, `auth_config.json` та `finance_assistant.db`** у відкритих репозиторіях. Ці файли вже додані до `.gitignore`.
- Використовуйте надійний майстер-пароль під час першої реєстрації у додатку.
- За можливості увімкніть **Windows Hello** у налаштуваннях ОС для швидкої та безпечної біометричної верифікації.

## Reporting a Vulnerability / Повідомлення про вразливість

Якщо ви виявили вразливість у системі безпеки проєкту:

1. **Не створюйте публічний GitHub Issue** з описом експлойту.
2. Надішліть детальний опис проблеми автору проєкту через профіль GitHub: [@oleksandrmyhydiuk](https://github.com/oleksandrmyhydiuk).
3. У повідомленні вкажіть:
   - Опис вразливості та потенційний вплив;
   - Кроки для відтворення (Steps to Reproduce);
   - За можливості — пропозиції щодо виправлення.

Ми розглянемо ваше звернення протягом **48 годин** та випустимо відповідний патч безпеки.
