# Звіт-ретроспектива: Реалізація системи безпеки та біометричної аутентифікації
**Проєкт:** Фінансовий Асистент (Financial Assistant)
**Модуль:** Безпека та Аутентифікація

## 1. Вступ
Для захисту фінансових даних користувача було вирішено впровадити систему входу. Окрім стандартного пароля, було поставлено амбітну задачу реалізувати підтримку системної біометрії (Windows Hello) для швидкого входу. Для цього було використано стек бібліотек: `argon2-cffi`, `keyring` та `winsdk`.

---

## 2. Бібліотека `argon2-cffi` (Хешування паролів)

### Задачі та вибір
**Задача:** Безпечне збереження пароля користувача. Зберігати паролі у відкритому вигляді (plain text) є неприпустимим з точки зору кібербезпеки.
**Чому ця бібліотека:** Алгоритм Argon2 є переможцем конкурсу Password Hashing Competition і рекомендований сучасними стандартами (OWASP) як надійніший за застарілі `bcrypt` чи `pbkdf2`. Бібліотека `argon2-cffi` є офіційним та найшвидшим Python-баіндингом для цього алгоритму.

### Досвід використання
* **Встановлення:** Тривіальне (`pip install argon2-cffi`).
* **Використання:** API надзвичайно просте та інтуїтивне. Клас `PasswordHasher` надає лише два необхідні методи: `hash()` (для реєстрації) та `verify()` (для перевірки). Це мінімізує ризик помилки розробника.
* **Проблеми:** Жодних проблем не виявлено.
* **Позитивні аспекти:** Автоматичне керування сіллю (salt) та параметрами складності. Розробнику не потрібно вручну налаштовувати криптографічні примітиви.

## 3. Бібліотека `keyring` (Безпечне сховище)

### Задачі та вибір
**Задача:** Збереження токена підтвердження для біометричного входу.
**Чому ця бібліотека:** Ми не можемо зберігати "дозвіл на вхід без пароля" у звичайному JSON-файлі, адже зловмисник міг би просто скопіювати його. Бібліотека `keyring` надає інтерфейс до **системного сховища секретів** (Windows Credential Manager), доступ до якого захищений операційною системою.

### Досвід використання
* **Зрозумілість:** Бібліотека працює як словник: `set_password(service, user, pass)` та `get_password(...)`. Це максимальна абстракція від складних системних викликів.
* **Взаємодія:** Чудово інтегрується в логіку програми. Якщо Windows вимагає авторизації для доступу до Credentials, бібліотека прозоро очікує на це.
* **Позитивні аспекти:** Кросплатформеність. Якщо перенести код на macOS, він автоматично почне використовувати Apple Keychain без зміни коду.

## 4. Бібліотека `winsdk` (Windows Hello / Біометрія)

### Задачі та вибір
**Задача:** Виклик нативного вікна Windows Hello для сканування обличчя або відбитка пальця.
**Чому ця бібліотека:** Це єдиний спосіб отримати доступ до сучасних API Windows 10/11 (Windows Runtime API) з Python без написання C++ обгорток. Аналоги відсутні або застарілі.

### Складність та документація
**Оцінка складності:** 9/10 (Висока).
Це була найскладніша частина лабораторної роботи.
* **Документація:** Офіційна документація Microsoft орієнтована на C# та C++. Доводилося "перекладати" логіку з C# на Python, здогадуючись про назви методів у пакеті `winsdk`.
* **Асинхронність:** Windows API для біометрії (`UserConsentVerifier`) є асинхронним. Python `winsdk` використовує `async/await`. Інтеграція асинхронного коду в синхронний GUI додаток вимагала використання `asyncio.run()`, що є нетривіальним.

### Проблеми та їх вирішення
**Головна проблема:** Зависання графічного інтерфейсу (GUI).
Коли викликався метод `asyncio.run(check_async())`, головний потік програми блокувався в очікуванні відповіді від камери/сканера. Вікно програми ставало неактивним ("Не відповідає").

**Рішення:**
Було застосовано патерн багатопоточності.
1.  Створено окремий клас `BiometricThread`, що успадковує `QThread` (з бібліотеки PyQt5).
2.  Виклик `auth_manager.verify_biometrics()` перенесено в метод `run()` цього потоку.
3.  Результат передається назад у GUI через механізм сигналів (`pyqtSignal`), що є потокобезпечним способом.

### Висновок по winsdk
Це потужний, але "низькорівневий" інструмент. Він дає крутий результат (справжній FaceID у Python-програмі!), але вимагає глибокого розуміння асинхронності та потоків.
